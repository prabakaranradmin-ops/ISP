Installation · Windows

Getting ISP BSS/OSS running on a Windows machine

Everything below happens on the machine that will run the software — a dedicated server or a well-specced desktop. No Docker, no separate database install: one file lays down the whole stack.

01What the machine needs

RequirementDetail
Operating systemWindows 10, Windows 11, or Windows Server 2019+ (64-bit)
Administrator accessRequired to run the installer — it registers Windows services and writes to Program Files
Disk space~2 GB free (the installer bundles its own PostgreSQL database engine)
NetworkPort 443 (HTTPS, console & portal) and UDP 1812/1813 (RADIUS) reachable from wherever staff and routers connect from

Nothing else needs to be pre-installed. PostgreSQL, the web server, and the RADIUS service all ship inside the one installer file.

02What gets installed

The installer places everything under Program Files\ISP BSS and registers three Windows services, so the software starts itself on every boot without anyone signing in:

Service nameWhat it does
ISPBSSPostgresThe database — starts first, everything else depends on it
ISPBSSApiThe website: staff console, customer portal, and Wi-Fi sign-in page
ISPBSSAaaCoreRADIUS — talks to your routers, authenticates customers, enforces plan speeds
i

Settings and generated passwords live separately, under ProgramData\ISP BSS\config, so an upgrade or repair can safely replace the program files without touching them.

03Run the installer

You'll have received one file: ISP-BSS-Setup-1.0.0.msi. The easiest path uses the deploy script that ships alongside it — it handles elevation, service stop/start, and a health check in one go.

  1. Copy ISP-BSS-Setup-1.0.0.msi and the installer folder onto the target machine (or the whole project folder, if you have it).
  2. Open the installer folder and double-click deploy.bat.
  3. Windows will ask permission to make changes to your device (User Account Control). Click Yes — a new window opens to do the actual work; the one you clicked closes, which is expected.
  4. Wait for it to finish. On a first install this takes a couple of minutes: it lays down the files, initializes the database, generates secrets, and starts all three services.

Prefer a standalone window instead of a browser tab (no address bar, no tabs — closer to a real desktop app) for showing this to someone? Run deploy.bat -AppMode instead of double-clicking it.

Installing without the script

If you'd rather not use deploy.bat, the MSI works on its own from an elevated Command Prompt or PowerShell:

PowerShell · run as Administrator
msiexec /i "ISP-BSS-Setup-1.0.0.msi" /l*v install.log

The trade-off: you stop the three services yourself first if this is an upgrade over a running install, and you open the console yourself afterward. deploy.bat exists specifically to remove those manual steps.

04Sign in for the first time

On first boot, the installer creates exactly one staff account — the owner — with a randomly generated password, and writes it to a text file that only exists on this machine:

Where to find it

C:\ProgramData\ISP BSS\config\initial_admin.txt
  1. Open that file in Notepad. It contains a username and a password line.
  2. Go to https://<this machine's address>/staff/login — https://localhost/staff/login if you're sitting at the machine itself.
  3. Your browser will warn that the certificate isn't trusted — this is a self-signed certificate the software generates for itself, not a sign anything is wrong. Proceed anyway (usually "Advanced → Continue").
  4. Enter the username and password from the file and sign in.
!

Do this next, before anything else: once you're in, open Change password (top right) and set a real password, then delete initial_admin.txt. It's the only copy, and anyone who can read that file on disk can sign in as the owner.

Need more staff accounts — for a NOC engineer, a billing admin, a CSR, a technician? Create them from Staff Accounts in the console itself; see the Operations Guide.

05Confirm it's healthy

deploy.bat already checks this for you and prints it at the end of the run. To check it yourself at any time, from an ordinary (non-elevated) PowerShell window:

PowerShell
Get-Service ISPBSSApi, ISPBSSAaaCore, ISPBSSPostgres

curl.exe -sk -o NUL -w "readyz -> %{http_code}`n" https://localhost/readyz

All three services should read Running, and the health check should read 200.

06Installing a newer version later

Run deploy.bat again, pointed at the new MSI. This is a genuine in-place upgrade, not an uninstall followed by a fresh install — Windows Installer replaces the old version and lays down the new one as a single operation, so your database and settings are never touched.

Command Prompt
deploy.bat "D:\path\to\ISP-BSS-Setup-1.1.0.msi"
i

Only need to change what's installed, not reach for a full teardown? A genuine wipe-and-reinstall — for troubleshooting a corrupted install — is available as an explicit extra step: deploy.bat -FullReinstall. Ordinary upgrades never need it.

07Uninstalling

From Settings → Apps, remove ISP BSS/OSS like any other Windows program, or run deploy.bat -FullReinstall without a follow-up install if you just want it gone. Either way, your database (pgdata) and configuration are left on disk afterward — uninstalling removes the software, not the data it was holding.

08If something goes wrong

You seeWhat's actually happening
A dialog listing programs to close, during installAn older version's files are in use. Let it close them, or stop the three services yourself first, then retry.
"Another program is being installed" 1500A previous install/uninstall didn't finish cleanly. Reboot the machine to clear it, then run the installer once more — do not run uninstall and install back-to-back, which is what causes this.
A service won't startCheck the full run log at installer\dist\install.log for the exact error near the end of the file.
